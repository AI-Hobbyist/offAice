# MCP 与 AGENTS 使用说明

## MCP 配置

从“设置与连接 → MCP 工具”管理全局配置；选择配置范围可管理某个项目。也可以在项目菜单选择“MCP 配置…”或点击项目会议室的 MCP 图标。

AIROOM 独立保存配置。Codex、Claude Code、Claude Desktop、ChatGPT 导出和自定义文件只用于导入，不会被回写或实时跟随。“默认导入来源”只选择下次导入入口，不改变现有服务。先预览再应用；应用会替换当前范围的导入快照，保留手工配置。无效或重复名称配置不会部分写入。

- **stdio**：启动命令可直接填写已安装的名称（如 `codegraph`、`minecraft-dev-mcp`、`npx`），也可填写完整路径；参数单独填写 JSON 数组。AIROOM 依次查找项目及父目录的 `node_modules/.bin`、PATH、npm 全局目录和 nvm 已安装版本，自动解析 npm/Node 启动脚本并保留对应 Node 和启动参数。可设置工作目录；相对工作目录以项目根目录解析，留空使用执行目录。AIROOM 不替服务安装其依赖。
- **HTTP**：填写 Streamable HTTP MCP 地址，可配置 headers 或 Bearer Token。旧 HTTP+SSE 不属于本期支持范围。
- **项目覆盖**：同名项目配置整条覆盖全局配置；禁用可屏蔽全局同名服务。删除手工配置恢复导入或继承值。
- **测试连接**：仅初始化并读取工具列表，不调用工具。点击后确认信任再执行。结果按配置保存；改动服务后旧结果失效。
- **超时**：连接测试和支持对应选项的执行端使用所设超时；其他执行端遵循原生设置。

Claude、Codex、DSH 的 stdio 与 HTTP 已完成实际模型调用验证。其他 ACP 程序根据其能力声明接入；HTTP 不受支持时会明确报错。ZCode 暂无已核验的配置入口，当前明确报告不支持，不会忽略配置后伪称成功。

例如 CodeGraph：命令填 `codegraph`，参数填 `["serve", "--mcp"]`。Minecraft Dev MCP：命令填 `minecraft-dev-mcp`，参数填 `[]`。保存后点击“测试连接”。连接测试和正式执行使用相同的命令解析，不再需要手动拆出 npm 启动器背后的 JavaScript 路径。

外部服务不受模型沙箱约束。因此仅在允许修改、联网、命令和任意文件范围时启用；只读、普通会议聊天及受限场景保持关闭。项目首次使用或配置变化时确认服务信任。密钥和参数回读显示为圆点，保留圆点即保留原值。配置加密保存在 AIROOM 数据库，保护密钥由 Windows 系统凭据保护保存；迁移到其他 Windows 用户时需重新导入/配置，不能复制密钥冒充原账号。

## AGENTS 工作约定

全局文件位置：`%USERPROFILE%\.airoom\AGENTS.md`。
项目文件位置：该项目绑定的根目录下 `AGENTS.md`，不以临时任务副本为配置来源。

使用 UTF-8 保存所需约定。文件不存在时按未配置处理。每轮开始读取；修改或移除从下一轮生效，不改动正在执行的轮次。

角色卡独立保存且完整保留，AGENTS 不覆盖角色卡提示词。用户明确指令优先；角色卡优先于 AGENTS；工作约定冲突时项目优先于全局。工作约定不会写入其他产品的配置或角色卡中。

## 绿色版

完整解压 ZIP 后运行 `AIROOM.exe`。无需另装 Node.js；开发环境现已安装 nvm Node.js 26.13.0。

压缩包仅包含应用及运行依赖，不包含个人配置、聊天、账号、MCP 密钥或测试资料。日常数据仍保存在用户目录的 `.airoom\data`。关闭窗口会缩至托盘，完全退出使用托盘的“退出 AIROOM”。
